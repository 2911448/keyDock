# KeyDock 验证记录

环境：Apple Silicon，macOS 27.0，Xcode 27 beta / Swift 6.4。部署目标 macOS 14，实际未在 macOS 14 设备运行。

## 2026-09-14 / 1.1.0 应用功能绑定

- 31 项 XCTest 全部通过（19 项 App、12 项 Core），Release arm64 构建及严格签名校验通过。沿用原 Apple Development 签名身份，未修改或重置系统权限。
- 新增测试覆盖 v1 无损读取与首次保存备份、普通／菜单／快捷键绑定共存并往返 JSON、功能切回普通绑定、无效功能拒绝、合成事件完整松键及防止监听器递归触发。事件测试不向系统投递事件。新增录制阶段拦截测试，确认组合键、重复按下和配对松开不传递给其他应用。
- 实机微信 4.1.7.2：自动读取 72 个菜单功能，可搜索完整路径并选择；通过「测试」执行“微信 → 关于微信”，实际出现关于微信界面。
- 同一临时 X 键通过录入 Command+I 保存为手动功能；退出重启后名称、组合键、先激活选项和功能标记恢复，点击 X 键帽实际打开微信关于页。测试完成已从 UI 清除该临时绑定、关闭验证用微信设置窗口并退出编辑模式。
- 测试成功后面板保持收起，再次打开会恢复未保存草稿；防止截图过程中面板自动弹回。普通应用的原有切换分支保持不变。
- 原有 7 个应用绑定、前缀和呼出键与备份逐项相同。首次测试保存已迁移为 v2，原始 v1 文件完整保留为 Application Support/KeyDock/settings.v1-backup.json。

- 待实机补测：实体组合键触发功能、微信截图后台模式、首次后台启动后功能就绪、权限撤销、应用语言变化与菜单禁用、外接键盘、多屏和 macOS 14。

## 2026-09-14 / 1.0.4 回归

- 用户截图显示「无法隐藏 WeChat」。旧逻辑在 NSRunningApplication.hide() 返回 false 时立即报错，没有回退方式或最终状态确认。
- 增加 ApplicationHider：先发送原生隐藏请求，等待主 RunLoop 更新；未隐藏时通过现有辅助功能授权写入目标应用的 AXHidden 属性。IPC 放到后台且设置超时，返回主线程异步确认 isHidden。请求被接受但未真正隐藏不会误报成功。
- 隐藏期间按应用去重；下一次有效操作清除旧错误。未改变用户绑定和系统授权。
- 新增 5 项测试覆盖原生失败后回退、原生延迟成功、请求成功但状态不变、授权拒绝和应用中途退出。全部 25 项 XCTest、Release arm64 构建及签名验证通过。
- 实机使用微信登录窗口，通过 A 键帽显示，再次点击 A 隐藏；设置中显示「已隐藏 WeChat」，该状态仅在实际 isHidden 为 true 后写入。未操作微信登录。版本 1.0.4，监听正常。
- CUA 组合键尝试没有可靠进入全局事件监听，因此此次确认的是面板调用所用的真实应用切换路径，不能声称实体 Control+A 已实测。原有配置 SHA-256 保持不变。
- API 依据：[Apple NSRunningApplication.hide](https://developer.apple.com/documentation/appkit/nsrunningapplication/hide())、[Apple AXHidden 属性](https://developer.apple.com/documentation/applicationservices/kaxhiddenattribute)；本机 SDK 说明 hide 返回的是请求是否发送成功，isHidden 跨主 RunLoop 更新。

## 需要系统授权或额外环境的验收

1.0.3 已显示监听正常；以下完整清单尚未全部实测，不能将纯逻辑测试等同于全局监听验收：

1. A 绑定 Safari，完成编辑。在其他 App 中按 Control+A，首次启动 Safari，再次隐藏，再次恢复；长按不循环切换。
2. 快速双击 Control 呼出/收起，慢双击、Control+A、左右 Control 同时按、Control 与其他修饰键混用不误呼出。
3. 面板呼出后按 A 或点击 A，行为一致；以前台 Safari 呼出时调用 A 应隐藏它。Esc 或点击外部关闭；关闭后普通输入正常。
4. 未绑定的 Control+B 正常传递；Control+Shift+A 不匹配 Control+A。改用 Option 后旧前缀立即失效，新前缀生效。
5. 搜索/编辑不触发全局绑定；暂停后双击/全局组合不触发，但菜单栏和面板点击仍可用。
6. 权限撤销后状态变为不可用；恢复权限后自动恢复，必要时依 macOS 提示重启应用。睡眠唤醒后不出现粘键和双击残留。
7. 中文输入法和 Caps Lock 下物理 A 仍匹配。真实 Fn／地球键检测、外接键盘与系统快捷键冲突提示符合实际结果。
8. 多屏按鼠标所在屏幕居中；全屏 App / 不同 Space 中可呼出；深色模式、较小屏幕和辅助功能减少透明度设置下检查显示。
9. 移动绑定的第三方 App 后尝试按 bundle identifier 定位；卸载后显示错误，重新绑定恢复；已关闭所有窗口的 App 再次调用可重新打开窗口。
10. 开启登录项并获得系统批准后重新登录，检查后台启动；关闭后再次登录不启动。测试后按用户选择保留登录项状态。
